Fluxo de uma reserva (resumo)

  1. Frontend chama POST /api/reservas com Bearer JWT; o API Gateway valida o token no authorizer.
  2. A Lambda reservas consulta o Verified Permissions (IsAuthorized(CriarReserva)).
  3. Com ALLOW, grava reserva e evento no mesmo TransactWriteItems (META, PRES/SOLI, VERS, CTRL condicional e OUTBOX).
  4. Conflito de versão retorna 409; em sucesso, publica PutEvents (ReservaCriada/Alterada/Cancelada) e remove o item do OUTBOX.
  5. EventBridge aciona o Step Functions, que executa Notificador (e-mail via SES) e Cliente SNP em paralelo, de forma idempotente.
  6. Falhas após retries caem na DLQ SQS; o Republicador (rate 1 min) reenvia itens restantes do OUTBOX.
